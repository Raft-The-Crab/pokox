# Security Policy

## Reporting a vulnerability

**Do not open a public issue for a security vulnerability.**

Report suspected vulnerabilities privately to the project maintainers:

- Use GitHub's private vulnerability reporting ("Security" → "Report a
  vulnerability") if the repository has it enabled; or
- Contact a project maintainer directly through the project's normal
  private channels.

Please include:

- a description of the issue and its potential impact;
- steps to reproduce or a proof of concept;
- affected component(s) (engine, platform, RHI, backend, client, etc.);
- any suggested mitigation, if known.

## What to expect

- We will acknowledge receipt as soon as practical.
- We will investigate, reproduce, and assess severity.
- We will coordinate a fix and disclosure timeline with you before any
  public details are published.
- We do not currently offer a bug bounty.

## Scope notes

- This repository contains planning documents, engine foundations, and
  asset tooling. Much of the planned attack surface (network protocol,
  economy ledger, moderation) is not yet implemented.
- Reports about the legal document drafts under `docs/legal/` should go
  through the maintainers; those drafts require counsel review and are
  not shipped policy.

## Supported versions

Only the current development branch is supported. There are no released
versions yet.
