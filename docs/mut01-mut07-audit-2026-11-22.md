# MUT-01–07 follow-up audit — 2026-11-22

## Scope

Reviewed the current lexer, arithmetic parser, numeric evaluator, debug-console input/print adapter, initial function interpreter and new control flow, along with tests, ownership, budgets, source placement and integration boundaries. This follows, rather than supersedes, the more detailed MUT-01–05 and MUT-01–03 reports. It is a local targeted review, not proof that the project is defect-free or a security certification.

## Finding fixed

The demo previously decided whether the input was full by inspecting a fixed buffer position rather than the current NUL-terminated text. Pinned ImGui copies only through the new terminator when input is shortened, leaving older bytes beyond it. After a full input was shortened, an old nonzero byte could therefore cause a false “Input limit reached” rejection. The UI now searches within the bounded span for the first terminator, rejects missing/full/zero-capacity buffers, and ignores stale trailing bytes. Tests cover shortened, full, unterminated and zero-capacity buffers. The debug heading was changed from “Mute arithmetic console” to “Mute console” to reflect its program support. Input remains bounded; a truly full field is not executed.

## Checks and remaining limitations

- MUT-01/02: pinned Unicode tables, malformed UTF-8, token and AST goldens, precedence and parser reference tests remain covered. Full Mute grammar and static checking are not implemented.
- MUT-03: checked numeric arithmetic and evaluator reference tests remain covered. The exhaustive signed/unsigned 8-bit binary-operation suite exercises 655,360 cases. Float equivalence and 10k-tick cross-platform replay remain unproven.
- MUT-04/05: console and print tests include byte caps, formatting, sink errors and escaped ASCII controls. The log is not a Unicode-bidi/format-control sanitizer; print is still a narrow top-level bridge, not the general VM hostcall.
- MUT-06/07: direct/mutual recursion, local scopes, reassignment, booleans, branching, loops, return propagation, short-circuiting, error ordering, budget boundaries, nested execution, finite generated cases and malformed inputs are covered. Each loop check consumes budget, so even an empty infinite loop traps. Runtime steps are not VM instructions and do not bound wall-clock work or total memory. Diagnostics/type resolution are runtime and path-dependent; unexecuted branches are not statically checked.
- Locations remain consistent with the existing layout: `mute/include/poko/mute` for public APIs, `mute/src` for implementation, `mute/tests/unit` for unit tests, and `engine/render/tests/integration` for the graphics interaction test. No new directories were required.
- The earlier intermittent X11 `X_GetImage`/`BadMatch` in the cube-golden harness remains unresolved: reruns previously passed but the root cause was not established. Software Vulkan and synthetic keyboard tests cannot substitute for physical GPU, IME, Windows/MSVC, Android or hosted CI testing. The graph extractor skipped 155 files and partially extracted the demo at its preprocessor conditional near line 245; its graph is not complete. Both debug and release-strip demo variants did compile in the actual graphics build.
- Parsing and evaluation can allocate and may propagate allocation failures. UI execution is synchronous and the logical budget is not a guaranteed frame-time bound. Unicode display-spoofing, comprehensive sandbox limits, production scheduling, finalized language semantics and inherited platform/determinism gates remain open.
