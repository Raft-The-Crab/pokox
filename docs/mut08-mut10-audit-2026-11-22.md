# MUT-08–10 implementation progress and audit — 2026-11-22

## Summary

This is a **partial implementation**, not completion of MUT-08, MUT-09 or MUT-10. The earlier local MUT-01–07 audit remains applicable. No G1/G2, hosted CI, Windows or Android gate is waived. Existing Mute program and console execution still call the tree-walk interpreter, so existing programs and top-level print do not run through this VM.

## Work added

- **MUT-08 groundwork:** `poko/mute/register_vm.hpp` provides an experimental 256-cell, signed i32 register machine for arithmetic, integer comparisons, branches, moves and returns. Register 0 is forced to zero and cannot be an instruction destination. Execution validates the instruction stream before running, uses checked arithmetic, rejects invalid budget limits, and charges every instruction. It is a standalone host API, not the Mute language runtime.
- **MUT-09 groundwork:** `mute/tools/math_determinism.py` compares raw binary64 sin/cos outputs for a fixed 36-case input corpus. It requires exact order, version agreement, distinct target labels and matching bit patterns, rejecting missing, extra, malformed and duplicate records. It **does not implement math**, generate traces, prove target provenance or check numeric accuracy. It is a comparison tool, not evidence of determinism by itself.
- **MUT-10 groundwork:** `poko/mute/bytecode.hpp` and `mute/src/bytecode.cpp` add an experimental version-1 `MUTB` wire codec, limited opcode disassembler, bounded instruction validation and binary round trips. See `mute/BYTECODE-EXPERIMENT.md` for the encoding, constraints and compatibility warning.
- Code lives under `mute/include/poko/mute`, `mute/src`, `mute/tests/unit` and `mute/tools`. CMake builds it into the existing `poko_mute_program` static library; it does not change the debug console execution path.

## Audit findings and open work

### MUT-08 — high: language integration missing

The VM does not compile or execute source programs, support function calls, locals/scopes, typed boolean semantics, print/hostcalls, constants, source spans, stack traces, floating values, heap, production traps or sandbox quotas. Its initial register contents are supplied by the embedding host; comparisons produce 0 or 1 and branches interpret zero/nonzero. These semantics are not a commitment for full Mute. Validation checks opcode shapes, reserved operands, register-zero writes and branch destinations; it is **not** a type, initialization, capability or control-flow verifier. Never treat this prototype as safe for untrusted bytecode. Before replacing the existing interpreter, implement a bounded source-to-bytecode pipeline, calls and frame semantics, preserve error and side-effect ordering and define budget accounting. Differentially test the entire MUT-01–07 language and console behavior, including short-circuiting, recursion, budget boundaries and print.

### MUT-09 — high: deterministic math not ported or validated

The tree-walk evaluator uses native floating operations; this work does not add deterministic sin/cos or expose them to Mute. Choose an appropriately licensed, vetted implementation and pin its version, binary format, input domain, precision/accuracy, range reduction, rounding mode, FMA/fast-math settings, subnormal handling, NaNs, infinities and signed zero semantics. Obtain independent expected-value/accuracy evidence as well as raw-bit traces from real Windows x64, Linux x64 and Android arm64 under documented builds. Comparing labels or two local copies is not proof that traces came from different architectures. G1/G2 replay remains separately required.

### MUT-10 — high: format is provisional and incomplete

The spec gives four 8-bit fields yet claims a 24-bit displacement in `b|c`, which has 16 bits. This prototype chooses signed 16-bit relative displacement for experimentation only, without changing the authoritative specification. Resolve and version the real ISA with the owner before adopting or persisting it. The prototype supports only the listed opcode subset and does not include the planned full constant pool, functions, hostcalls, metadata, source mappings, extended instructions, assembler or production verification. Its `MUTB` format is **not** `.pkB` and must not be shipped as a stable format. Binary decode→encode and disassembly goldens alone do not prove full ISA or program round trips.

### Integration finding fixed

The version-integration test builds a minimal copied source tree. Adding the two new translation units initially caused its configure step to fail because the fixture did not copy them or their headers. The fixture now copies all four files, and the complete strict suite passes. The first sanitizer run also lacked the sandbox-local ASan runtime on its library path; rerunning with the provided runtime resolved that environment issue.

### Other limits

- Stream validation is linear in code size (maximum 65,536 instructions) and occurs before the instruction budget starts; allocation and host time are not bounded by that budget. VM calls do not allocate after validation, but codec and disassembler can allocate and propagate allocation failure. Callers must prevent concurrent modification of borrowed instruction spans.
- Branches targeting outside the stream, malformed opcode shapes, reserved operand misuse and writes to r0 are rejected. Reaching end-of-code or `halt` without a return is a runtime error. The VM does not guarantee all reachable paths return or that values have intended types.
- Audit coverage includes local targeted tests; it is not a security certification, an exhaustive whole-project review, or proof of no defects. The earlier unresolved X11 screenshot-harness issue, Unicode display concerns, synchronous console timing and platform gaps remain open.

## Verification

Linux strict GCC `-Wall -Wextra -Wpedantic -Werror`: 58/58 tests passed. GCC ASan/UBSan with the local sanitizer runtime: 58/58 passed. An isolated software-Vulkan/Xvfb configuration passed 81/81 tests; its console still exercises the existing tree-walk path. The graphics configure emitted dependency CMake deprecation warnings. No ARM or Windows execution was available; these results do not close cross-platform gates. The added tests cover binary goldens and round trips, truncation, invalid headers/opcodes/operands/targets, max stream size, signed branch extremes, step budgets, arithmetic overflow/divide traps, a register loop, randomized arithmetic comparisons against the existing evaluator, and malformed/mutated inputs. The comparator tests check matching, mismatching and malformed traces; the sample matching data is synthetic, not architecture evidence.
