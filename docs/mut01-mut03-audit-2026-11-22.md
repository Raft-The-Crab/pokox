# MUT-01–MUT-03 integration audit (2026-11-22)

> Historical audit. For the follow-up fixes and remaining findings, see `mut01-mut03-followup-audit-2026-11-22.md`.

## Scope

Reviewed the lexer/Unicode tables, arithmetic parser/owned AST, new evaluator, CMake wiring, byte-exact goldens, test fixtures and archive layout. This is a focused Mute audit, not a repeat of the full ENG-01–22 audit or proof that the entire project is defect-free. Earlier infrastructure and device/CI gates remain open.

## Findings and action

1. **Fixed — host FP traps could terminate evaluation.** The initial floating-point environment probes and arithmetic could execute with host FP exceptions unmasked. The evaluator now saves the floating environment, masks traps while checking and evaluating, and restores it on normal return; setup/check/normal-path restoration failures return `unsupported_float_environment`, with a restoration attempt during exception unwinding. Tests unmask the x86 SSE overflow trap and verify the diagnostic and exact control/status restoration, and verify caller exception flags survive. This does not prove all platform fenv implementations.
2. **Open — deterministic floating point is not yet established across platforms.** The evaluator fails closed for unrecognized compiler flags, non-nearest rounding and detected flush-to-zero/denormals-are-zero. Local f32/f64 bit-pattern comparisons and environment probes pass, but decimal conversion and floating behavior have not been validated on Windows/MSVC or Android arm64, and no 10,000-tick cross-platform replay exists. No deterministic gate is accepted.
3. **Open — numeric contract is partial/provisional.** Float remainder is explicitly unsupported, unsigned unary minus is rejected, and overflow/nonfinite handling follows the baseline in `../mute/ARITHMETIC-EVALUATOR.md`; the design must settle those choices. Identifiers have no binding environment. Consequently the evaluator is not a complete implementation of all Mute expressions.
4. **Open — resource limits are incomplete.** The evaluator enforces a configurable AST-node cap, but lexer/parser source size, AST allocation and total memory are not bounded by a sandbox. The node cap is not the specified VM instruction/heap budget. Callers must bound source size; MUT-07/VM resource enforcement remains future work.
5. **Open — platform and pipeline validation.** Hosted CI, current Windows/MSVC/MinGW and Android runs are unverified; Git autocrlf simulation is not a Windows build. The real graphics configuration still emits 21 upstream CMake deprecation warnings and Xvfb nonfatal keyboard-map warnings. The graph refresh omitted unsupported files and reported stale labels.

## Evidence

- Nine MUT-02 AST/error goldens and fourteen MUT-03 result/error goldens use the shared byte-exact harness and reject deliberately corrupted results. Unicode generator tables are compared against the pinned UCD. Existing lexer/parser error, nesting and ownership tests remain active.
- An independent Python oracle compared 600 generated i32 expressions, 500 typed integer boundary cases, and 400 bounded f32/f64 bit-pattern cases. An opt-in optimized exhaustive test checked all 655,360 signed and unsigned 8-bit operand/operator combinations for `+ - * / %`, including overflow and zero divisors. These do not prove all 64-bit or all IEEE inputs.
- A clean extraction of the archive built with strict warnings-as-errors and passed **54/54** CTest entries.
- The final Linux/GCC strict suite passed **54/54** entries; ASan/UBSan with leak detection passed **54/54**; real SDL3/pinned Diligent software-Vulkan/Xvfb passed **70/70** including the unchanged cube golden. Tests include doubles, not exclusively live-device tests. A `core.autocrlf=true` temporary Git checkout preserved all 65 Mute fixture/UCD files byte-for-byte.

## Reproduce the exhaustive audit

```sh
cmake -S . -B build-mute-exhaustive -DCMAKE_BUILD_TYPE=Release -DPOKO_MUTE_EXHAUSTIVE_TESTS=ON
cmake --build build-mute-exhaustive --target poko_mute_evaluator_i8_exhaustive
ctest --test-dir build-mute-exhaustive -R '^mute_evaluator_i8_exhaustive$' --output-on-failure
```
