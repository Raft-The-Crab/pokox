### Findings to address

1. **ENG-15: pending GPU timing can be lost.** `imgui_demo.cpp` uses one duration query, calls `GetData` after each frame, then begins the same query on the next frame even if its result was not ready. In the pinned Diligent Vulkan backend, `OnBeginQuery` calls `AllocateQueries`, which first discards the previous query. GPU samples can therefore be dropped or remain unavailable under GPU latency. The ImGui duration path was not built or exercised in this Linux environment. Fix with a tested pending-query or query-ring lifecycle; do not interpret a missing sample as zero-duration work.
2. **ENG-17: `ready` means worker completion, not necessarily acquisition readiness.** `load_state()` returns `ready` for a finished result awaiting `poll_async()`, while `acquire()` still returns an invalid handle for that job. The public comments require polling, but the meaning of `ready` is easy to misinterpret. Clarify or redesign this contract and add a regression test before consumers rely on it.
3. **ENG-04/05 and platform gates remain open.** The real fallback built, but this Xvfb display had no sRGB GLX visual, so OpenGL color parity and resize were not tested. Physical GPU testing of this revision, Windows MSVC, GitHub CI, Android and high-DPI resize remain outstanding. Windows AMD results in historical progress notes predate the corrected camera and KTX2 revisions and do not verify these current changes.
4. **Integration coverage is incomplete.** Real full-manifest vcpkg/ImGui/Catch2 integration was not exercised in this environment. ImGui's keyboard/text, general textures and non-Vulkan paths remain incomplete. KTX2 upload is not connected to the async asset queue. The frame graph remains a CPU-only logical scheduler, not GPU barrier management. Warning-free builds are not claimed: the Diligent checkout emits 19 upstream CMake deprecation warnings, and the virtual X server may emit nonfatal keyboard-map warnings.
5. **Shader target is Vulkan 1.1.** The configured compiler emits SPIR-V 1.3 for `--target-env vulkan1.1`; a Vulkan 1.0 validator intentionally rejects it. The current target validated with `spirv-val --target-env vulkan1.1`. Vulkan 1.0 compatibility is not claimed.

## ENG-21 implementation

`DirectionalLight` validates and normalizes the world-space **surface-to-light** direction, keeps the prior value when input is zero or non-finite, and packs it with ambient in a 16-byte std140 vector. The mesh pass creates and binds a dynamic fragment uniform before SRB creation and updates it per draw. The Lambert shader safely treats a zero normal as ambient-only; positions/normals and light are currently all world-space with identity model transform. `pokox_cube --light x y z` supplies an initial direction; hold left/right arrow keys to rotate it live. Left-drag still orbits the camera.

The pass now explicitly resets its old resource binding before pipeline recreation; the camera API comment was corrected to describe the actual identity default. No general material system, model/normal matrix, multiple lights, shadows, OpenGL/ES lighting, or golden-image test is implied. The shader and executable need to be rebuilt together; an old fragment shader does not contain the new uniform.
